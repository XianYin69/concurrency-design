# 协程（coroutine / green thread / 轻量任务）

来源：[本地]（未联网确证）· 用途：区分「并发单位」的成本模型。

## 形态

- **栈式有调度器**（Go goroutine、Kotlin/coroutines、Python trio/asyncio task、
  Java 虚拟线程 Loom）：可挂起点在任意调用深度，M:N 调度到少量 OS 线程。
- **无栈状态机**（C++20 协程、Rust async）：挂起点编译期已知，零堆分配但需小心生命周期。
- **生成器式**（Python `yield`、Lua coroutine）：手工驱动，适合协作式流水线。

## 高频结论

1. 协程便宜 ≠ 可无限创建：仍受内存、句柄、下游连接池约束 → 必须限并发（信号量/池）。
2. **线程钉住（pinning）**：协程内调用阻塞 API 会占住载体线程（Java `synchronized` 块、
   本地 JNI）→ 高并发下退化为线程模型，须改锁或加池。
3. 局部变量隔离是优点，但共享闭包捕获外部变量会重新引入竞态。
4. 取消必须成树传播（结构化并发），否则出现「孤儿协程继续写数据」。
5. 调度公平性与栈增长是尾延迟来源，须以 P99 观测而非平均值判断。

## 选型判据

- 大量等待（IO/锁/队列）→ 协程；大量计算 → 线程/进程池或并行算法；
  混合 → 协程接入 + 计算池，边界处显式转换与限流。
