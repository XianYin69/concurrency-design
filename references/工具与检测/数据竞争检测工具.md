# 数据竞争与死锁检测工具（TSan / Helgrind / DRD / JCStress）

来源：[本地]（未联网确证版本与选项）· 用途：为「有竞态/无竞态」提供可复核证据。

## 工具矩阵

| 工具 | 层次 | 检什么 | 代价 | 注意 |
|---|---|---|---|---|
| ThreadSanitizer (TSan) | 编译/运行期插桩 | 数据竞争、锁序问题、部分原子性 | 5-15x 慢、内存翻倍 | 需 `-fsanitize=thread`，与 ASan 互斥 |
| Helgrind / DRD（Valgrind） | 模拟层 | pthread 锁误用、顺序不一致 | 20-50x 慢 | 对自旋/原子不敏感 |
| JCStress | JVM 专用 | JMM 下的可见性/重排、断言失败剖面 | 需专门用例 | 报告含线程交错统计 |
| Java `-XX:+UnlockDiagnosticVMOptions` / JFR | 运行期 | 锁争用、阻塞时长 | 低 | 定位瓶颈非证明正确 |
| Go `-race` | 编译插桩 | 数据竞争、部分死锁提示 | 5-10x | 测试与生产构建分开 |
| Rust `-Z sanitizer=thread` / loom / shuttle | 多法 | 竞态、调度交错穷举 | loom 需改写 | 模型检查非全覆盖 |
| Python `faulthandler` / `threading` 审查 | 运行期 | 死锁挂起栈、GIL 语义 | 低 | 无成熟 race 检测器 |

## 用法要点

1. **检测器只覆盖执行到的交错**：0 报告 ≠ 无竞态，须配合多轮压力与随机化调度。
2. 报告须落档：命令、版本、编译选项、用例、结论，写入 `tmp/test-report.md`。
3. 误报处理：加抑制文件（`.supp`）须逐条说明理由，禁止整体关闭检测。
4. 与静态剖面互补：`race_probe.py`/`thread_safety_lint.py` 找可疑点 → 检测器确证 → 压测复现。
