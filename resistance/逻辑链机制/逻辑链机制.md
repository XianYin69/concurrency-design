# 逻辑链机制

每个决策必须留痕：frm → to → why，可回溯、可复盘、可仲裁。

## 必须

1. 决策点写链：
   `python -B scripts/logic_chain.py add logic_chain.jsonl --from <起点> --to <结论> --why <理由>`。
2. 审查节点跑正反双链：
   `python -B scripts/logic_chain.py debate --pro <正方> --con <反方>`，裁决仍记 add。
3. 链文件落 tmp（收尾随产物释放），禁止写入缓存目录之外。
4. 收口前校验：`python -B scripts/logic_chain.py verify logic_chain.jsonl` 缺字段 = 0。
5. 高危节点（grant danger / 云端下载 / 对外端口）除链外还须回人在回路。

## 禁止

- 无 `--why` 的空洞条目（等于没记）。
- 事后补写与真实执行不符的「美化链」。
- 用链替代用户确认——涉及不可逆动作仍须询问。

## 违规后果

- 缺链 → 无法解释为何选此方案，审查与复盘失效；
- 假链 → 误导后续会话，错误被固化进知识。
