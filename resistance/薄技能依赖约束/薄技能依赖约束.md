# 薄技能依赖约束

**红线**：本技能本体保持薄；能力一律经 `dependence/dependence.md` 声明获取，
禁止把其他技能正文内嵌进本目录。

## 必须

1. 每项能力在 `dependence/` 有一行声明：`名称 | skill|software|repo | 来源`。
2. 调用依赖前先自检：`python -B scripts/deps_check.py --dependence dependence/dependence.md`。
3. 依赖缺失：记 `process_chain.py interrupt` 并向用户报告缺项，禁止伪造能力继续。
4. 跨技能调用只传「意图 + 参数」，由对方技能在其自身目录内执行。
5. 新增/删除依赖须走 [update 审批流](../../update/update.md) 并记 CHANGELOG。

## 禁止

- 复制他技能 SKILL.md / 脚本正文进本技能目录（含改名后内嵌）。
- 直接 import 其他技能目录内的模块（耦合即违反薄技能原则）。
- 在 references/ 或 asset/ 中夹带依赖技能的实现细节。
- 声明未使用的依赖（虚增攻击面与安装成本）。

## 违规后果

- 内嵌副本随上游演进而失真，产生「文档与实现不一致」的隐性缺陷；
- 跨目录 import 使技能无法独立安装/迁移/回收；
- 依赖未声明 → 目标机器上静默失败，用户无法预判前置条件。
