# 共享可变状态约束（领域红线）

本约束规定并发实现中不可让步的正确性底线。违反者不得进入整体审查。

## 必须

1. 每处可变状态须声明**归属**：单线程 confined / 线程间共享 / 不可变；无归属＝需求未确认。
2. 共享可变状态**只能**经一种机制访问：锁、原子变量、消息传递（channel/actor）、或只读快照；
   混用须写明为何两种机制不会互相破坏。
3. 可见性显式化：跨线程读写的字段须用语言提供的可见性手段（`volatile`/`atomic`/锁内访问/
   `final`+安全发布），禁止裸字段跨线程读写。
4. 复合操作（读-改-写、check-then-act、lazy init）须原子化：锁、CAS 重试、或原子 API；
   禁止「看起来只有一条赋值」即认定原子。
5. 优先不可变：能 `final`/`const`/只读快照/复制后替换（copy-on-write）就不共享可变对象。
6. 安全发布：构造完成的对象才暴露给其他线程；禁止 `this` 逃逸与半初始化对象外泄。
7. 每个共享状态须有**不变量**文字说明（何时成立、由谁维持），并写入代码注释与 references。
8. 交付前须有竞态证据：`race_probe.py` 剖面 + 至少一轮 `stress_test_runner.py` 重复执行结果。

## 禁止

- 用「加 sleep 后不复现」「降低并发度就没事」当作修复；竞态未消失只是概率掩盖。
- 用无同步的 double-checked locking（除语言/库提供安全发布保证者，如 Java `volatile` DCL）。
- 以 `Thread.yield`/自旋无上限代替正确同步；自旋须有退避与进展保证。
- 在信号处理/异步回调里持锁或调用非异步安全函数。
- 把「加锁」当成万能答案而不审视状态归属与粒度（见 [锁粒度约束](../锁粒度约束/锁粒度约束.md)）。

## 兜底

- 无法即时改造（遗留大泥球）：先加**串行化边界**（单线程 owner + 队列）隔离风险，记逻辑链与中断。
- 语言/库无相应原子原语：改用消息传递或集中式单线程状态机，并在 references 标注差异。
- 无法复现的偶发竞态：转 [浏览器学习](../../branch/流程/浏览器学习/浏览器学习.md) 查检测工具，
  用 TSan/Helgrind/压力重复执行取证，禁止猜测式改动。

## 违规后果

- 未声明归属的共享状态 → 数据竞争、未定义行为、线上偶发脏数据且不可复现。
- 无可见性手段 → 读到过期值，锁形同虚设。
