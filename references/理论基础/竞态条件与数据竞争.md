# 竞态条件与数据竞争（二者不是一回事）

来源：[本地]（未联网确证）· 用途：区分缺陷类型并选对检测手段。

## 区分

- **数据竞争 data race**：两个线程访问同一内存位置、至少一个是写、无同步且顺序不确定 —— 是**内存级**问题。
- **竞态条件 race condition**：程序正确性依赖并发事件的**时序** —— 是**逻辑级**问题，
  可以完全没有数据竞争（如两个都通过锁访问，但业务顺序错了：TOCTOU、检查后执行）。
- 关系：数据竞争常导致竞态条件；消除数据竞争（加锁）**不等于**消除竞态条件。

## 常见形态

| 形态 | 说明 | 修法 |
|---|---|---|
| 读-改-写丢失 | `count++` 交错 | 原子/CAS/锁 |
| check-then-act | 先查再改（TOCTOU） | 把检查与动作放进同一原子域 |
| 发布竞态 | 半初始化对象外泄 | release/acquire、不可变快照 |
| 初始化竞态 | 双重检查非安全 | 语言提供的 once/lazy 原语 |
| 时序依赖 | 依赖「A 先到」 | 显式屏障/握手/状态机 |
| 顺序破坏 | 依赖重排不发生 | 内存序 + 不变量说明 |

## 检测

- 静态：`race_probe.py` / `thread_safety_lint.py` 剖面（启发式，须复核）。
- 动态：TSan / Helgrind / DRD / JCStress（见 [数据竞争检测工具](../工具与检测/数据竞争检测工具.md)）。
- 复现：提高并发度 + 多轮重复执行（`stress_test_runner.py`），随机化调度。

## 用法

1. 报告缺陷时先分类：内存级还是逻辑级，决定用 TSan 还是不变量测试。
2. 「加锁后不复现」不足以结案，须能说明不变量在哪个原子域内成立。
