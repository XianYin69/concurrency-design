# 上下文压缩机制

约束长上下文的取舍，保证关键决策不丢失、噪声不占预算。

## 必须

1. 长文档进上下文前先压缩：
   `python -B scripts/context_compress.py --ratio 0.3 --kw <关键词> --path <文件>`。
2. 压缩后必须保留：需求判据、接口签名、红线条目、失败证据、出处 URL。
3. 压缩产物落 tmp，禁止覆盖原文；引用时注明「压缩摘要·非全文」。
4. 每轮预算超限（见〔Token 预算〕提示）即自行分段/拆多轮，不得硬塞。
5. 关键结论另存逻辑链，压缩可丢、链不可丢。

## 禁止

- 用压缩摘要充当「已验证事实」（须回原文或联网确证）。
- 丢弃失败日志与报错原文——它们是诊断的唯一依据。
- 为省 token 跳过流程节点的必读文档。

## 违规后果

- 摘要当事实 → 幻觉实现与错误结论；
- 丢日志 → 同一故障反复重试，触发惩罚熔断。
