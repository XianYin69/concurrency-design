# git 工作流约束

本项目采用严格的功能分支策略，保障历史可追溯、可回滚、可合入。

## 规则

1. **启动前拉取**：工作前 `git fetch`；有远端更新先 `git pull --ff-only`，不得忽略。
2. **功能分支提交**：每步完成后提交到 `feature/<topic>`，分支名不得为 main 或 dev。
3. **审核通过合 dev**：双链辩论（logic_chain.py debate）+ 悬空链接 = 0 后合入 `dev`。
4. **整体审查通过合 main**：九项标准全部通过后 `dev` 合入 `main`，并推送 main 与 dev。
5. **禁止直写 main/dev**：所有变更须经功能分支进入 dev。
6. **重试熔断**：审查失败重试达 10 次触发 penalty.py 熔断，回退分支或求助用户。
7. **忽略清单**：`.gitignore` 须含 `tmp/` 与 IDE 目录；暂存前核对 `git status`。
8. **自动 git init**：无 `.git/` 即先 `git init`，不得跳过。
9. **推送前确认**：推送远端前必须询问用户，确认后才 `git push`。
10. **高危门禁**：git 写操作属高危，须用户当轮确认 + `grant danger`（SMS 守卫会拦截）。

## 违规后果

- 跳过功能分支 → main/dev 被污染，无法按步骤回滚；
- 忽略远端更新 → 本地与远端分叉产生冲突；
- 跳过审核 → 问题代码直接发布；
- 漏配 ignore → 临时产物入库污染历史；
- 未确认即推送 → 未经同意发布到远端。
