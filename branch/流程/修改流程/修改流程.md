# 修改流程

独立路径：修改既有代码或既有技能，不接在收尾之后。

## 动作

1. 定位：`git log --oneline` + grep 确认改动范围与受影响接口。
2. 需求确认：改什么、为什么改、验收判据（同 [需求确认](../需求确认/需求确认.md) 清单）。
3. 影响分析：调用方、数据契约、测试覆盖；列回归风险清单。
4. 开功能分支 `feature/<topic>`，禁止直改 main/dev。
5. 实施：最小改动优先；同步更新测试与文档，禁止只改代码不改说明。
6. 回归：`run_tests.py` 全绿；不明处走 [浏览器学习](../浏览器学习/浏览器学习.md)。
7. 审查：九项标准子集（链接、体量、约束、测试）→ 合 dev → 整体通过后合 main。
8. 标记「完成项目修改」，收口返回调度方整合续排。

## 禁止

- 未跑回归即交付；删除既有测试来「让绿灯亮」。
- 顺手重构超出需求范围（另开功能分支）。
