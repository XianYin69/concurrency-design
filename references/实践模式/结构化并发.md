# 结构化并发（structured concurrency）

来源：[本地]（未联网确证）· 用途：把并发任务的生命周期约束在词法作用域内。

## 核心思想

- 「一个挂起/派生 = 一个作用域」：父作用域退出时，**所有**子任务必已终止（完成/失败/取消）。
- 由此消灭三类顽疾：孤儿任务、泄漏线程、异常跨线程静默丢失。
- 失败策略由作用域定义：`all-of`（一败即全撤）/ `any-of`（首个成功即撤其余）/ 监督重启。

## 代表实现

| 平台 | 原语 |
|---|---|
| Java 21+（Loom） | `StructuredTaskScope`（`try (var scope = new StructuredTaskScope.ShutdownOnFailure())`） |
| Python trio / asyncio | `nursery` / `TaskGroup`（3.11+ `asyncio.TaskGroup`） |
| Kotlin | `coroutineScope { }` / `supervisorScope { }` |
| Go | `errgroup.Group` + `context`（`wg.Wait()` 收口） |
| .NET | `Task.WhenAll` + `CancellationTokenSource` 链接（无原生作用域） |

## 高频结论

1. 取消沿树传播，异常沿树汇总 —— 二者必须同时成立，否则「结构化」只是语法糖。
2. 版本敏感：`StructuredTaskScope` 在 JDK 预览与正式之间有过 API 变更，
   用到即须浏览器学习确证当前版本语义。
3. 与线程池不冲突：作用域管生命周期，池管执行资源；池的拒绝策略仍须显式选择。
4. 遗留代码改造顺序：先加「等待与收口」（join/when_all），再谈取消传播，最后谈失败策略。
