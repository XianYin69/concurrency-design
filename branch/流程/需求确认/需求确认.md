# 需求确认
接收并发任务后先澄清，再动手；区分创建 or 修改。
## 必答清单
1. **工作负载**：任务是 CPU 密集还是 IO 密集？并发规模（线程/协程/连接数）与到达模式。
2. **语言与运行时**：Java/C++/Go/Rust/Python/.NET 及**具体版本**、调度模型（线程/协程/混合）、
   是否受 GIL/GOMAXPROCS/虚拟线程等约束。
3. **共享状态**：哪些数据被跨线程访问、读写比例、是否可改为不可变或单 owner。
4. **一致性要求**：需要线性化/顺序一致/最终一致？可容忍的丢更新、重复执行、乱序是什么。
5. **活性与资源**：超时上限、取消语义、吞吐/尾延迟目标、池与队列上界、背压策略。
6. **验收标准**：可执行判据（无数据竞争报告、锁序无环、压测 N 轮 0 失败、取消在 X 秒内收敛；
   无判据＝需求未确认）。
7. **路径判定**：新建并发组件/服务 → 创建流程；改既有实现/脚本/技能 → 修改流程。
## 动作
- 缺项一次一问向用户确认（`ask_user`），禁止用假设填补关键需求（尤其运行时版本与取消语义）。
- 每条判定写逻辑链：`python -B scripts/logic_chain.py add logic_chain.jsonl --from 需求确认 --to <判定> --why <理由>`。
- 存档：`python -B scripts/process_chain.py save --step 需求确认 --data '{"...": "..."}'`。
## 兜底
- 需求持续模糊：出流程图辅助澄清（`scripts/flowchart_helper.py`），仍不明则熔断求助。
- 无法确知负载量级：按最坏并发度评估锁争用与队列上界，并在大纲标注假设。
