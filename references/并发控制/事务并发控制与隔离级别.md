# 事务并发控制与隔离级别（应用侧并发）

来源：[本地]（未联网确证）· 用途：把「线程并发」与「事务并发」两套语义对齐。

## 两套并发控制

- **进程内**：锁/原子/消息传递（本技能主场）。
- **数据库**：2PL、时间戳排序、乐观校验、MVCC + 快照、SSI 谓词依赖检测。
  两者可叠加：应用持锁不能阻止数据库内冲突，反之亦然。

## 隔离级别与异常（ANSI 四级 + 引擎现实）

| 级别 | 脏读 | 不可重复读 | 幻读 | 备注 |
|---|---|---|---|---|
| READ UNCOMMITTED | 可能 | 可能 | 可能 | 几乎不可用 |
| READ COMMITTED | 否 | 可能 | 可能 | 常见默认（PG/Oracle） |
| REPEATABLE READ | 否 | 否 | 标准定义可能 | PG=SI，存在写偏斜 |
| SERIALIZABLE | 否 | 否 | 否 | PG SSI 报 `40001` 须重试 |

- 异常清单：丢失更新、写偏斜（write skew）、幻读、读偏斜（read skew）、重复序列化。
- 引擎细节（InnoDB next-key lock、PG SSI、Oracle ORA-08177）**属须确证项**，须经浏览器学习。

## 应用侧对策

1. 悲观：`SELECT ... FOR UPDATE`（+ `SKIP LOCKED` 做任务队列）。
2. 乐观：版本号/CAS 更新（`UPDATE ... WHERE version = ?`），失败重试须有上限与退避。
3. 幂等：唯一约束/去重键承担最终一致性，不依赖应用查重（并发下必失效）。
4. 事务内禁止外部 IO；跨服务用 Saga/Outbox，不用分布式长事务。
