# 脚本构建
按大纲与分支裁决写并发实现与检测脚本；本体薄，规范与范式经依赖获取。
## 动作
1. 脚手架：`python -B scripts/scaffold_project.py --target tmp/<proj> --layout src,tests,bench`。
2. 实现顺序：先「串行正确」再并发——单线程版本通过断言后，才引入线程/锁/通道。
3. 同步落地：按大纲锁表写锁与编号；复合操作使用原子 API 或锁；跨线程发布使用约定机制。
4. 静态体检：`python -B scripts/race_probe.py tmp/<proj>` 与
   `python -B scripts/thread_safety_lint.py tmp/<proj>`，错误清零才进构建测试。
5. 访问层准则：调用 [code-guidelines](../../../dependence/dependence.md) 取命名/复杂度准则，
   [pavedpath-code](../../../dependence/dependence.md) 取已验证范式（线程池/管道/工作窃取）。
6. 单文件 ≤50 行：超限即拆「入口脚本 + 模块」。
7. 每步提交功能分支 `feature/<topic>`（见 git 工作流约束）。
## 禁止
- 臆造 API/内存序/库默认行为：任何不确定的原子语义、锁属性、取消机制须经
  [浏览器学习](../浏览器学习/浏览器学习.md) 取证。
- 用 `sleep`/降低并发度/重试「让测试变绿」（见 [共享可变状态约束](../../../resistance/共享可变状态约束/共享可变状态约束.md)）。
- 未声明锁序的多锁路径、锁内阻塞 IO（见 [锁粒度约束](../../../resistance/锁粒度约束/锁粒度约束.md)）。
- 缺失终止路径的实现（见 [取消安全约束](../../../resistance/取消安全约束/取消安全约束.md)）。
- 静默写盘：默认 `--dry-run`，落盘须显式 `--yes`。
