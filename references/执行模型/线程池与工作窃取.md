# 线程池与工作窃取

来源：[本地]（未联网确证）· 用途：执行器选型与池大小/队列裁决。

## 结构要素

- **池大小**：CPU 密集 ≈ 核数；IO 密集按 `核数 × (1 + 等待时间/计算时间)` 估，须压测修正。
- **队列**：有界（背压）/无界（OOM 风险）/直接交付（SynchronousQueue）；
  无界队列 + 固定池 = 延迟无上界（见 [背压与限流](../并发控制/背压与限流.md)）。
- **拒绝策略**：调用者运行 / 丢弃 / 抛错 / 降级入队 —— 必须显式选择并说明后果。
- **工作窃取（fork/join）**：每线程双端队列，空闲时从他人队尾偷 → 递归分治与不规则任务扩展性好。

## 高频结论

1. **线程池自死锁**：任务内提交并等待子任务，池满即锁死 → 分层池或禁止内联等待。
2. 池大小不是越大越好：上下文切换与内存占用随线程数上升，扩展性拐点须实测。
3. 任务须**短且可取消**；长任务占坑导致饥饿 → 拆分或改协程。
4. 窃取粒度：阈值以下改为串行计算，否则窃取开销超过收益。
5. 观测指标：队列深度、拒绝次数、任务 P99 等待时间、线程利用率 —— 无指标即无调优依据。

## 跨语言对应

Java `ThreadPoolExecutor`/`ForkJoinPool`；.NET TPL `TaskScheduler`；Go `GOMAXPROCS` + M:N 调度；
C++ `ThreadPool`（自实现或 TBB）；Python `concurrent.futures`（GIL 限制 CPU 并行，多进程替代）。
