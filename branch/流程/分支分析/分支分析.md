# 分支分析
对大纲的每个岔路做正反双链自辩，再定执行模型/同步策略分支。
## 分析维度
1. **执行模型**：OS 线程 / 线程池 / 协程 / actor-CSP / 事件循环，按等待占比而非偏好选择
   （见 [`references/执行模型/`](../../../references/执行模型/协程.md)）。
2. **同步策略**：锁 / 原子 / 不可变快照 / 消息传递 / 无锁结构（见
   [`references/数据结构/`](../../../references/数据结构/锁与无锁数据结构.md)）。
3. **一致性强度**：线性化 vs 最终一致 vs 无要求，决定是否需要 CAS/事务/幂等键（见
   [`references/理论基础/`](../../../references/理论基础/内存模型与happens-before.md)）。
4. **过载策略**：有界队列 + 拒绝 / 限流 / 降级 / 扩容（见
   [`references/并发控制/`](../../../references/并发控制/背压与限流.md)）。
5. **风险分支**：死锁与锁序、伪共享、线程池自死锁、锁内阻塞 IO、不可取消调用、取消被吞。
## 动作
- 每个岔路一次辩论：`python -B scripts/logic_chain.py debate --pro <正方> --con <反方>`，裁决记逻辑链。
- 结论落 `tmp/branch-decision.md`：选项、裁决、理由、被否方案、影响的并发度与量级。
- 任一维度信息不足（某运行时内存序默认、库 API 语义、版本行为）→ 立即转
  [浏览器学习](../浏览器学习/浏览器学习.md)。
## 兜底
- 双链势均：选**不变量更易证明、回滚更容易**的一支（通常是粗锁 + 有界队列），并记 TODO 复验。
- 无法确证运行时行为时，禁止按其他语言类推写实现；降级为「只出方案不出代码」并告知用户。
