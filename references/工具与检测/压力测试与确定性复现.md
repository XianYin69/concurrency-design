# 压力测试与确定性复现

来源：[本地]（未联网确证）· 用途：把「偶发」变成「可复现、可回归」的证据。

## 复现策略

1. **提高交错概率**：加大并发度、缩短临界区外耗时、注入随机 sleep/让出（时序植入）。
2. **多轮重复**：同一用例跑 N 轮（`stress_test_runner.py --threads --rounds`），统计失败率。
3. **缩小规模**：把生产并发缩到 2-3 线程 + 关键路径，更易定位且仍能复现。
4. **确定性化**：用可控调度器/虚拟时钟（Python `trio` mock clock、Java `jcstress`、
   Rust `loom`、Go 手工 `channel` 同步）把交错固定成可断言序列。
5. **记录种子**：随机化必须打印随机种子，失败可回放。

## 度量

| 指标 | 意义 |
|---|---|
| 失败率 / 复现轮次 | 竞态概率，判「修好了没」 |
| P50/P99 时延 | 锁与队列的真实代价 |
| 吞吐拐点（并发度 vs QPS） | 池大小与锁粒度依据 |
| 挂起线程数 | 取消/超时路径是否有效 |

## 断言写法

- 不变量断言优先于「结果相等」：如 `sum(增量) == 最终值`、`无重复消费`、`无孤儿记录`。
- 每次修复须留下**回归用例**（能失败 → 修复后通过），否则视为未修。
- 压测环境（核数、JIT、依赖服务）须写入报告，跨环境结论不可直接迁移。
