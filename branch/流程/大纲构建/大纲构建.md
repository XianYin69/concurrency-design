# 大纲构建
把需求拆成状态归属、执行模型与同步结构，形成可审阅的实现大纲。
## 动作
1. **状态清单**：每个可变数据标「归属」（confined / 共享 / 不可变）与不变量说明。
2. **执行单元**：线程/协程/actor 的数量、生命周期、创建与终止路径（正常/超时/取消/失败）。
3. **同步结构**：锁表（锁 → 保护字段 → 编号）、原子变量、队列/通道（容量与满时行为）。
4. **锁序约定**：给出全局加锁顺序表，供 `deadlock_check.py` 验环。
5. **过载与取消**：背压点、超时值来源、取消传播链、失败后的状态自洽方式。
6. **命名与布局**：`src/`、`tests/`、`bench/`（准则见 [dependence/](../../../dependence/dependence.md)）。
7. **风险点标注**：伪共享、线程池自死锁、锁内阻塞、不可取消的第三方调用 → 交分支分析与浏览器学习。
8. 大纲交用户审阅确认后再进入分支分析；确认结论写逻辑链。
## 产出
- `tmp/outline.md`：状态表 + 锁表与锁序 + 执行单元表 + 取消/背压方案（≤50 行，超则拆子文档）。
- 每单元一条 `process_chain.py save --step 大纲构建 --data '{"unit":"..."}'`。
## 兜底
- 大纲与需求冲突：回 [需求确认](../需求确认/需求确认.md) 重澄清，禁止私自缩减范围。
- 规模过大：先切 MVP（单一串行化边界 + 关键路径）交付，其余列 TODO 并告知用户。
